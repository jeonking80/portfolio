# 테스트

## 원칙

- 미실행·실패·차단을 통과로 적지 않습니다.
- 시험 개수는 자동화 시험의 실행 수입니다. 작성량이 아닙니다.
- CI 대신 저장소에 들어 있는 로컬 검사(`./scripts/check-local.sh`)로 검증합니다.

## 층별 시험

| 층 | 확인하는 것 | 도구 |
| --- | --- | --- |
| 단위 | PLC 판정, 상태 전이, 정산 계산, 권한 표 | pytest |
| 계약 | 태그 48개, 명령·사건·전송 메시지 형식, 직렬화 | pytest · Pydantic |
| 통합 | 실제 PostgreSQL에서 수집·중복 제거·잠금·트리거·마이그레이션 | Docker PostgreSQL |
| 종단 | 설비 앱 → OPC UA → 게이트웨이 → API → DB → 브라우저 | Playwright · Chromium |
| 화면 | 화면 상태 계산, 입력 검증 | Node 시험 |
| 장시간·성능 | 30분 통신 단절 복구, 7일 이력 조회 | 전용 실행기 |

## 시험으로 고정한 실패 상황

- 명령 응답 유실 → 원래 ID로 결과만 조회하고 새 ID로 재실행하지 않음
- 같은 수집 묶음 재전송 → 실적 한 번만 반영
- 같은 ID에 다른 내용 → 충돌 증거 저장, 스트림 차단
- 배출 확정 중 설비 앱 강제 종료 → 물품·수량·사건이 전부 남거나 전부 없음
- 조회 전용 사용자의 제어 요청 → 서버가 거절
- 인증서가 다른 OPC UA 연결 → 거절

## 하지 않은 것

- 실물 PLC·센서 연동. 설비와 PLC는 소프트웨어 시뮬레이터입니다.
- 공개 배포 환경의 성능 측정. 단절 복구·이력 조회 성능은 과거 로컬 구성에서만 측정했습니다.
- 8시간 연속 운전 시험.
- 수락 시험 T01~T12를 한 번에 묶은 실행. 17개로 나눠 각각 통과했습니다.
- 2026-10-23 이후 화면 개편과 품목 기준정보 도입에 맞춘 종단 시험 갱신. 최신 버전의 전체 통과는 아직 다시 확인하지 않았습니다.
