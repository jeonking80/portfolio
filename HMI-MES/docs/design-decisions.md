# 핵심 설계 결정

결정마다 어떤 문제를 풀려고 했는지, 무엇을 골랐는지, 어떤 대안을 버렸는지, 그 대가가 무엇인지 적었습니다.

## 1. 설비와 운영 시스템을 두 앱으로 나누고 OPC UA로만 연결

- **문제** — 운영 시스템 안에 설비 흉내를 넣으면, 통신 단절·응답 유실 같은 현장의 실패를 재현할 수 없습니다.
- **선택** — 설비 시뮬레이터(앱 B)를 별도 프로세스로 두고, 서명·암호화된 OPC UA로만 연결했습니다. 두 앱은 DB와 메모리를 공유하지 않습니다.
- **버린 대안** — 같은 프로세스 안에서 함수 호출로 흉내 내는 방식, 모의 HTTP.
- **대가** — 인증서·세션 관리가 복잡해졌고, 연결 실패 경로의 시험이 크게 늘었습니다.

## 2. 명령의 접수와 결과를 분리하고, 원래 ID로만 결과를 확인

- **문제** — 버튼을 눌렀다고 설비가 움직였다는 보장이 없습니다. 응답이 끊겼을 때 다시 보내면 같은 동작이 두 번 실행될 수 있습니다.
- **선택** — 명령을 원래 command_id로 원장에 저장하고, 접수(ACCEPTED)와 실행 결과(SUCCEEDED 등)를 따로 기록합니다. 결과를 모르면 `OUTCOME_UNKNOWN`으로 남기고 같은 ID로 조회만 합니다. 실행 허용 여부는 PLC가 판정합니다.
- **버린 대안** — 타임아웃 후 새 ID로 자동 재전송.
- **대가** — 작업자가 "결과 불명"을 직접 확인해야 하는 순간이 생깁니다. 두 번 실행되는 것보다 낫다고 판단했습니다.

## 3. 모르는 값은 모른다고 표시

- **문제** — 통신이 끊긴 동안의 값이 0이나 마지막 값으로 보이면, 작업자가 정상으로 오해합니다.
- **선택** — 측정값마다 품질과 시각을 함께 저장하고, 근거가 없는 구간은 "불명"으로 표시합니다. 대시보드의 가동률도 불명 시간을 가동이나 정지로 추정하지 않습니다.
- **버린 대안** — 마지막 값 유지, 0으로 채우기.
- **대가** — 짧게 운전한 날의 가동률이 낮게 보입니다. 화면에 그 이유를 적어 두었습니다.

## 4. 중복 제거·실적·처리 커서를 한 트랜잭션에

- **문제** — 재전송이나 재시작 때 같은 생산 사건이 두 번 들어옵니다. 셋을 따로 저장하면 실적이 두 번 잡히거나 커서만 앞서 나갑니다.
- **선택** — 사건마다 고유 event_id와 원래 execution_id를 붙입니다. 중복 제거, 실적 반영, 커서 전진을 한 트랜잭션에서 같이 커밋합니다. 게이트웨이는 커밋 ACK를 받은 뒤에만 버퍼를 지웁니다.
- **버린 대안** — "적어도 한 번" 전송 후 나중에 중복 정리.
- **대가** — 잠금 순서를 직접 관리해야 했습니다. 게이트웨이 → 스트림 → 사건 ID 순서이고, 사건 ID는 정렬해서 잠급니다.

## 5. 정산이 끝나야 다음 작업

- **문제** — 작업을 바꿀 때 라인 안에 남은 제품이 다음 작업의 수량에 섞입니다.
- **선택** — 종료 요청 → 신규 투입 중단 → 재공 정리 → 설비 최종 요약과 대조가 끝나야 다음 작업을 불러올 수 있습니다.
- **버린 대안** — 종료 버튼을 누르는 즉시 다음 작업을 연결.
- **대가** — 작업 전환 시간이 정산 확인만큼 길어집니다.

## 6. 이력은 DB 트리거로 보호

- **문제** — 애플리케이션 버그나 실수 한 번으로 취소·조치 이력이 고쳐지면 추적이 끊깁니다.
- **선택** — 21개 이력 테이블에 UPDATE·DELETE를 거절하는 트리거를 걸었습니다. 해당 테이블은 품목 변경, 등록 영수증, 작업지시 취소, 알람 조치, 정지 사유, 수집 시각 근거 등입니다. 정정은 새 기록으로 남깁니다.
- **버린 대안** — 애플리케이션 코드에서만 막기.
- **대가** — 보관 기간이 지난 기록을 정리할 때도 전용 함수와 절차를 거쳐야 합니다.

## 7. 작업지시는 유지하고 회차로 다시 실행

- **문제** — 처음에는 한 번 실행한 작업지시를 다시 쓸 수 없었습니다. 같은 제품을 또 만들려면 작업지시를 새로 등록해야 했습니다. 직접 화면을 써 보다 발견했습니다.
- **선택** — 작업지시는 유지하는 계획으로 두었습니다. 다시 불러오면 새 실행 ID를 발급하고, 실적은 회차별로 귀속합니다. 대기열 중복 방지는 대기 중인 항목에만 거는 부분 고유 인덱스로 바꿨습니다.
- **버린 대안** — 실행마다 작업지시를 새로 등록.
- **대가** — 작업지시 하나에 실행이 여러 개 연결되므로, 화면·보고서가 회차를 구분해 보여 줘야 합니다.

## 8. 무료 요금제로 공개 데모 운영

- **문제** — 공개 데모를 비용 없이 유지해야 했습니다.
- **선택** — Vercel 서버리스 함수와 Neon PostgreSQL 무료 요금제를 썼습니다. 함수는 화면·수집·분석 3개로 나눴습니다. 설비 쪽은 화면의 전원 요청이 있을 때만 켜지고 60분 뒤 자동으로 꺼집니다. 탭이 보이지 않으면 화면 폴링을 멈춥니다.
- **버린 대안** — 상시 서버와 유료 DB.
- **대가** — DB 사용량 한도가 있습니다. 실제로 한도를 넘겨 프로젝트를 한 번 옮겼습니다. 설비 쪽은 상시 연결이 아닙니다.
