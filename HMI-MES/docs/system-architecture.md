# 시스템 구조

## 전체 구성

```
┌───────────── 공개 클라우드 (무료 요금제) ─────────────┐
│  브라우저 · 웹 HMI/MES (React · TypeScript)            │
│        │ HTTPS · 세션 쿠키 · CSRF · Origin 검사        │
│  Vercel 서버리스 함수 (FastAPI) ──SQL── Neon PostgreSQL │
│   화면·제어 API / 수집 API / 분석 API                   │
└────────────────────────▲──────────────────────────────┘
                         │ HTTPS · 게이트웨이 서비스 토큰
                         │ 수집 묶음 / 명령 전달 · 결과 보고
┌────────────── 설비 쪽 (임시 클라우드 컨테이너) ─────────┐
│  I/O 게이트웨이 (SQLite 디스크 버퍼)   런타임 에이전트   │
│        │ OPC UA · Basic256Sha256 서명·암호화 · 인증서 검증│
│  앱 B 설비 시뮬레이터                                   │
│   투입 컨베이어 → 실링기 → 검사 배출기                   │
│   가상 Master PLC · OPC UA 서버 · SQLite 원장            │
└──────────────────────────────────────────────────────┘
```

KULS가 공개한 HMI 구성예시(현장설비 → Master PLC → OPC 서버 → HMI·MES 서버 → 모니터링)의 각 계층을 직접 구현했습니다.

## 구성 요소의 역할

| 구성 | 맡는 일 | 맡지 않는 일 |
| --- | --- | --- |
| 앱 A · 운영 시스템 | 인증·권한, 명령 원장, 수집, 작업지시, 정산, 보고서·트렌드·SPC | 운전 허용 여부 판정 |
| 앱 B · 설비 시뮬레이터 | 세 설비의 공정, 운전 조건 판정, 실행 결과 확정, 생산 사건 생성 | 앱 A의 DB 접근 |
| I/O 게이트웨이 | OPC UA 값 1초 수집, 묶음 전송, 명령 전달, 결과 조회 | ACK 전 버퍼 삭제 |
| 런타임 에이전트 | 화면의 전원 요청으로 설비 쪽 기동, 60분 뒤 자동 정지 | 운전 명령 |

두 앱은 DB와 메모리를 공유하지 않습니다. 게이트웨이와 브라우저는 DB에 직접 붙지 않고 API만 거칩니다. 분석 조회는 별도 함수로 나눠, 무거운 조회가 제어 API를 막지 않게 했습니다.

## 명령 하나가 처리되는 순서 (예: 일시정지)

1. 화면이 요청을 보냅니다. 서버가 세션·역할·CSRF·Origin을 검사합니다.
2. API가 명령을 **원래 command_id**로 명령 원장에 예약합니다. 이때 만료 시각도 함께 정합니다.
3. 게이트웨이가 예약된 명령을 가져가 PLC에 제출합니다. 접수(ACCEPTED)는 실행 성공이 아닙니다.
4. 게이트웨이가 같은 command_id로 PLC 결과를 조회해 API에 보고합니다.
5. 화면은 "요청 저장 → PLC 접수 → 실행 완료" 단계를 보여 줍니다.

응답이 중간에 끊기면 **새 ID로 다시 보내지 않습니다.** 결과를 모르면 `OUTCOME_UNKNOWN`으로 남기고, 원래 ID로 조회만 합니다.

## 수집 하나가 처리되는 순서

1. 게이트웨이가 OPC UA로 48개 태그와 생산 사건을 읽어 묶음을 만듭니다. 묶음은 디스크 버퍼에 먼저 저장합니다.
2. 수집 API가 한 트랜잭션 안에서 다음을 처리합니다(자세한 내용은 [핵심 코드 해설](ingest-explainer.md)).
   - 인증 범위 확인
   - 잠금
   - 같은 묶음인지 판별
   - 사건별 중복 제거와 실적 반영
   - 처리 커서 전진
   - ACK 저장
3. 커밋이 끝난 뒤에만 ACK를 돌려줍니다. 게이트웨이는 ACK를 받은 묶음만 버퍼에서 지웁니다.

## 작업 한 건의 흐름

작업지시 등록·배포 → 설비 전원 → 불러오기 → 예열(PLC 판정) → 생산 → 종료(재공 정리) → 정산(설비 최종 수량과 대조) → 다음 작업

같은 작업지시는 다시 불러와 여러 번 실행할 수 있습니다. 실행마다 새 실행 ID를 받고, 실적은 회차별로 따로 집계합니다.

## 역할과 권한

| 권한 | 조회자 | 작업자 | 생산 담당자 | 설비 관리자 |
| --- | :-: | :-: | :-: | :-: |
| 조회 | ● | ● | ● | ● |
| 운전(시작·일시정지) |  | ● |  |  |
| 작업 불러오기 · 종료 |  | ● | ● |  |
| 알람 확인·조치 |  | ● |  |  |
| 정지 사유 입력 |  | ● | ● |  |
| 작업지시 등록·배포, 공정 설정 관리 |  |  | ● |  |
| 설비 관리 |  |  |  | ● |

- **비밀번호:** scrypt로 저장합니다.
- **세션:** 30분 동안 쓰지 않거나 로그인 후 8시간이 지나면 끝납니다.
- **초기 비밀번호:** 바꾸기 전에는 운전할 수 없습니다.
- **쓰기 요청:** 모두 CSRF 토큰과 정확한 Origin 일치를 요구합니다.
